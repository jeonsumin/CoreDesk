# PRD: CoreDesk

## 목표

IT/소프트웨어 회사의 프로젝트·인력·자원 관리를 단일 플랫폼에서 처리해 업무 가시성과 생산성을 높인다.

---

## 1. 문제 정의 (Why We Build This)

### 현재 IT 회사의 고통점

| 고통 | 실제 상황 | 결과 |
|------|-----------|------|
| 정보 파편화 | 프로젝트 현황이 Slack·이메일·스프레드시트에 분산 | PM이 매일 수동으로 취합, 1~2시간 낭비 |
| 진행 불투명 | 팀원 진행 상황을 Slack 채널 하나하나 확인 | 병목 발견이 늦어 마감 초과 |
| 우선순위 혼란 | 개발자가 오늘 무엇부터 해야 할지 모름 | 급하지 않은 일 먼저 처리 |
| 보고 비효율 | 경영진 보고 자료 준비에 2~3시간 소요 | 반복 수동 작업, 리소스 낭비 |
| 온보딩 어려움 | 신규 멤버가 "내가 뭘 해야 하지?"를 모름 | 적응 기간 지연, PM 개입 증가 |

### CoreDesk가 해결하는 것

위 5가지 고통을 단일 플랫폼에서 해결한다. 모든 프로젝트·태스크·일정이 한 곳에 있고, 각 역할에 맞는 뷰를 제공한다.

- PM은 여러 프로젝트를 대시보드 한 화면에서 관리한다
- 개발자는 자기 태스크만 필터된 뷰에서 빠르게 상태를 업데이트한다
- 경영진은 읽기 전용 대시보드에서 리스크를 즉시 파악한다

## 2. 유저 페르소나

### 페르소나 A — 김지훈 PM (35세)

- **역할**: 시니어 프로젝트 매니저
- **상황**: 동시에 4~5개 프로젝트 진행, 팀원 10~15명 관리
- **목표**: 전체 진행 상황을 한눈에 보고 문제가 생기면 즉시 파악
- **고통**: "팀원한테 일일이 물어봐야 뭔 상태인지 알 수 있어요. 아침마다 Slack 정리하다 한 시간이 날아가요."
- **사용 패턴**: 출근 직후 대시보드 확인, 주 1~2회 마일스톤 점검, 팀원 태스크 재배정
- **핵심 화면**: 대시보드, 프로젝트 상세, 마일스톤, 멤버 관리

### 페르소나 B — 이수민 개발자 (28세)

- **역할**: 풀스택 개발자, 2~3개 프로젝트 동시 참여
- **상황**: 여러 프로젝트에 나뉘어 있어 무엇부터 해야 할지 판단이 어려움
- **목표**: 오늘 해야 할 일을 빠르게 파악하고 업무에 집중
- **고통**: "태스크 찾는 데 시간 써요. 프로젝트마다 채널 들락거리다 집중이 깨져요."
- **사용 패턴**: 하루 2~3회 접속, 태스크 상태 업데이트가 주요 행동
- **핵심 화면**: 내 태스크 목록, 태스크 상세, 상태 변경

### 페르소나 C — 박성호 대표 (45세)

- **역할**: CEO, 현황 열람 전용
- **상황**: 주간 경영 회의 때 프로젝트 현황을 보고받아야 함
- **목표**: 5분 안에 전체 현황과 리스크 파악
- **고통**: "보고 받을 때마다 자료 형식이 달라요. 어디가 문제인지 바로 보고 싶어요."
- **사용 패턴**: 주 1~2회 대시보드 접속, 수정 없이 읽기만 함
- **핵심 화면**: 대시보드 요약, 마일스톤 현황, 리스크 섹션

## 3. 유저 스토리

### PM (김지훈)

| ID | As a PM, I want to... | So that... | 인수 조건 |
|----|----------------------|------------|-----------|
| US-01 | 프로젝트를 생성한다 | 팀 작업을 시작할 수 있다 | 프로젝트명·기간·설명 입력 → 저장 → 목록에 즉시 표시 |
| US-02 | 팀원을 프로젝트에 초대한다 | 역할에 맞게 접근 권한을 줄 수 있다 | 이메일 입력 → 역할 선택(PM/Developer/Viewer) → 멤버 목록에 추가 |
| US-03 | 태스크를 만들고 담당자를 지정한다 | 누가 무엇을 해야 하는지 명확히 한다 | 태스크명·담당자·마감일·우선순위 입력 → 해당 멤버 뷰에 표시 |
| US-04 | 마일스톤을 설정한다 | 주요 납기 일정을 관리할 수 있다 | 마일스톤명·날짜 입력 → 목록 표시, 연결 태스크 수 자동 집계 |
| US-05 | 전체 프로젝트 진행률을 한눈에 본다 | 어느 프로젝트가 뒤처지는지 파악한다 | 대시보드에서 각 프로젝트 진행률 % 표시 |
| US-06 | 마감이 임박하거나 지연된 태스크를 파악한다 | 선제적으로 조치를 취한다 | D-3 이하 태스크에 경고 배지, 초과 태스크 빨간 강조 |

### 개발자 (이수민)

| ID | As a Developer, I want to... | So that... | 인수 조건 |
|----|------------------------------|------------|-----------|
| US-07 | 내가 담당한 태스크를 한 곳에서 본다 | 매번 프로젝트를 찾아다니지 않아도 된다 | "내 태스크" 뷰 → 전 프로젝트 걸쳐 내 태스크만 필터 |
| US-08 | 태스크 상태를 빠르게 업데이트한다 | 불필요한 클릭 없이 진행 상황을 반영한다 | 목록에서 드롭다운/버튼으로 상태 변경, 페이지 이동 없이 즉시 반영 |
| US-09 | 태스크 상세 내용을 확인한다 | 무엇을 어떻게 해야 하는지 파악한다 | 클릭 시 설명·마감일·우선순위·담당자 표시 |
| US-10 | 오늘/이번 주 마감 태스크를 빠르게 파악한다 | 우선순위를 스스로 판단할 수 있다 | 대시보드에 "오늘 마감", "이번 주 마감" 섹션 별도 표시 |

### 경영진 (박성호)

| ID | As an Executive, I want to... | So that... | 인수 조건 |
|----|-------------------------------|------------|-----------|
| US-11 | 전체 프로젝트 현황을 한눈에 본다 | 별도 보고 없이 상황을 파악한다 | 대시보드에 프로젝트별 상태·진행률·마감일 카드 표시 |
| US-12 | 리스크(지연 중인 프로젝트)를 식별한다 | 문제 프로젝트에 집중할 수 있다 | 마감 초과 or 진행률 50% 미만 + 마감 D-7 이하 프로젝트 강조 표시 |

## 4. 핵심 유저 플로우

### Flow 1: PM이 새 프로젝트를 셋업하는 플로우 (첫 사용)

```
[진입] 로그인 → 대시보드
  │  ← 프로젝트 없음 → 빈 상태 화면
  ↓
[빈 상태 CTA] "첫 프로젝트를 만들어보세요" 버튼 클릭
  ↓
[프로젝트 생성 폼]
  ├── 프로젝트명 (필수)
  ├── 설명 (선택)
  └── 시작일 / 종료일 (필수)
  → [저장] 클릭
  ↓
[프로젝트 상세 페이지 자동 이동]
  │  ← 가이드 배너: "팀원을 먼저 초대하세요"
  ↓
[멤버 탭] 이메일 입력 → 역할 선택 → [초대]
  ↓
[태스크 탭] [+ 태스크 추가] → 폼 작성 → 담당자 선택 → [저장]
  ↓
[마일스톤 탭] [+ 마일스톤 추가] → 이름 + 날짜 → [저장]
  ↓
[완료] 대시보드 복귀 → 프로젝트 카드 표시 + 진행률 반영
```

**UX 가이드 포인트:**
- 각 빈 상태마다 "다음 할 일" CTA를 명확히 표시 (사용자가 막힘 없이 이동)
- 프로젝트 생성 직후 멤버 탭으로 자동 포커스 이동 (또는 안내 배너)

---

### Flow 2: 개발자가 매일 아침 일과를 시작하는 플로우

```
[진입] 로그인 → 대시보드
  ↓
[오늘 마감 태스크 섹션] 확인 (D-day 기준 하이라이트)
  ↓
[사이드바] "내 태스크" 클릭
  ↓
[내 태스크 목록]
  ├── 전 프로젝트 걸쳐 내 태스크만 표시
  └── 우선순위·마감일 순 정렬
  ↓
[태스크 클릭] → 상세 확인 (설명, 마감일, 우선순위)
  ↓
[상태 변경] Todo → In Progress (목록에서 즉시 변경)
  ↓
  ... 작업 진행 ...
  ↓
[상태 변경] In Progress → Done
  │  ← 완료 시각적 피드백 (체크 애니메이션)
  ↓
[대시보드 복귀] 프로젝트 진행률 자동 업데이트 확인
```

**UX 가이드 포인트:**
- 상태 변경 시 확인 팝업 없이 즉시 반영 (마찰 최소화)
- 완료 처리 후 가벼운 시각적 피드백으로 성취감 제공

---

### Flow 3: 경영진이 주간 현황을 파악하는 플로우

```
[진입] 로그인 → 대시보드 (Viewer 권한, 읽기 전용)
  ↓
[요약 카드 섹션]
  ├── 전체 프로젝트 수
  ├── 진행 중 / 완료 / 보류
  └── 지연(마감 초과) 프로젝트 수 강조
  ↓
[리스크 섹션] 마감 D-7 이하 + 진행률 낮은 프로젝트 리스트
  ↓
[프로젝트 카드 클릭] → 프로젝트 상세 (읽기 전용)
  ├── 마일스톤 타임라인
  └── 태스크 현황 (완료 N / 전체 N)
  ↓
[뒤로 가기] → 다음 프로젝트 확인
```

**UX 가이드 포인트:**
- Viewer 권한은 생성·수정·삭제 버튼 완전 비표시 (권한 오류 노출 방지)
- 숫자와 시각적 차트 중심 레이아웃 (텍스트 최소화)

---

### Flow 4: 마감 위기 상황 대응 플로우

```
[진입] PM 로그인 → 대시보드
  ↓
[경고 배너] "마감 3일 이내 미완료 태스크 N개" 표시
  ↓
[배너 클릭] → 태스크 목록 이동 (마감 임박 필터 자동 적용)
  ↓
[태스크 목록] 우선순위 High로 변경
  ↓
[태스크 담당자 확인] → 과부하 멤버 발견 → 담당자 재배정
  ↓
[마일스톤 탭] 해당 마일스톤 날짜 연장 처리
  ↓
[대시보드 복귀] 진행 상황 재확인
```

**UX 가이드 포인트:**
- 경고 배너는 해소될 때까지 대시보드 상단에 고정
- 배너에서 문제 항목으로 원클릭 이동

## 5. 빈 상태(Empty States) & 온보딩 가이드

사용자가 빈 화면에서 막히지 않도록 각 상태마다 안내 문구와 다음 행동을 명시한다.

| 화면 | 빈 상태 메시지 | CTA |
|------|---------------|-----|
| 대시보드 (첫 로그인, PM) | "아직 참여 중인 프로젝트가 없어요. 첫 프로젝트를 만들어보세요!" | [+ 새 프로젝트 만들기] |
| 대시보드 (첫 로그인, Developer) | "아직 배정된 태스크가 없어요. PM에게 프로젝트 초대를 요청해보세요." | (버튼 없음) |
| 프로젝트 목록 | "프로젝트를 만들어 팀 작업을 시작하세요." | [+ 프로젝트 만들기] |
| 태스크 목록 (멤버 없음) | "태스크를 추가하려면 먼저 팀원을 초대하세요." | [멤버 초대하기] |
| 태스크 목록 (멤버 있음) | "아직 태스크가 없어요. 첫 태스크를 추가해보세요." | [+ 태스크 추가] |
| 내 태스크 | "담당 태스크가 없어요. PM에게 태스크 배정을 요청해보세요." | (버튼 없음) |
| 마일스톤 | "마일스톤을 추가해 주요 납기 일정을 관리하세요." | [+ 마일스톤 추가] |
| 멤버 목록 | "아직 초대된 멤버가 없어요. 이메일로 팀원을 초대해보세요." | [멤버 초대하기] |

## 6. 에러 & 엣지 케이스

| 상황 | 처리 방식 |
|------|-----------|
| 프로젝트 삭제 (하위 태스크 존재) | "태스크 N개와 마일스톤이 함께 삭제됩니다" 확인 모달 후 처리 |
| 멤버 제거 (담당 태스크 존재) | 태스크 담당자 → "미배정" 자동 변경, 프로젝트 내 알림 배지 표시 |
| 마감일 없는 태스크 | D-day 표시 대신 "-" 표시, 정렬 시 최하단 배치 |
| 마감일 초과 태스크 | 빨간 텍스트 + "D+N 초과" 배지, 완료 처리 전까지 유지 |
| Viewer가 수정 시도 | 버튼 자체를 비표시 (에러 메시지 노출 불필요) |
| 중복 이메일로 초대 | "이미 이 프로젝트의 멤버입니다" 인라인 에러 표시 |
| 시작일 > 종료일 입력 | "종료일은 시작일 이후여야 합니다" 폼 인라인 에러 |
| 태스크 마감일 > 프로젝트 종료일 | 경고 토스트: "태스크 마감일이 프로젝트 종료일을 초과합니다" |

## 7. 핵심 기능 명세 (MVP — 프로젝트 관리 모듈)

### 프로젝트 관리
- 프로젝트 생성·수정·삭제·보관
- 상태: `진행중` / `완료` / `보류` / `취소`
- 시작일·종료일 설정 및 완료 태스크 기준 진행률 자동 계산
- 목록 필터: 상태, 담당 PM, 기간

### 태스크/이슈 관리
- 태스크 생성·수정·삭제
- 상태 흐름: `Todo` → `In Progress` → `Review` → `Done`
- 우선순위: `High` / `Medium` / `Low`
- 담당자 배정 (프로젝트 멤버 중 선택)
- 마감일 D-day 표시 및 초과 배지

### 마일스톤/일정
- 마일스톤 생성·수정·삭제
- 연결 태스크 완료 비율 자동 집계
- 완료 여부 토글
- 기한 초과 시 시각적 경고

### 팀원/멤버 관리
- 이메일 기반 초대
- 역할: `PM` / `Developer` / `Viewer`

- 참여 중인 프로젝트 카드 (진행률, 마감일, 리스크 표시)
- 오늘 마감 / 이번 주 마감 태스크 섹션
- 전체 프로젝트 요약 수치 (역할별 뷰 상이)

- 모바일 앱

## 10. 비기능 요구사항

- 인증: 이메일+비밀번호 로그인, 세션 기반
- 권한: 역할(Role)별 UI 분기 및 API 접근 제어
- 반응형: 데스크톱 우선, 태블릿 지원
- 성능: 목록 페이지 LCP 2초 이내

---

## 11. 성공 지표 (MVP 기준)

- 프로젝트 생성 → 팀원 초대 → 태스크 배정 → 완료 처리까지 5분 이내 완료 가능
- 대시보드에서 전체 현황과 리스크 파악을 5분 이내에 가능
- 개발자가 로그인 후 30초 이내에 오늘 해야 할 일을 확인 가능
